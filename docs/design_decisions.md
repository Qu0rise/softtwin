# 設計判断の記録

決めたこと、そのとき比べた案、決め手を残す。数字の根拠は `results/` と `results/metrics.json` にある。

## D1. 柔らかい指は有限要素ではなく、擬似剛体モデル（PRBM）で近似する

- 比べた案：有限要素（SOFA、Isaac Sim の変形体）、PRBM（剛体の節＋関節のばね）
- 決め手：評価に数千試行が要る（Q1 と Q2 で約 3 000、頑健性で 2 100、判別マップで 480）。有限要素は 1 試行に数分かかり、固定シードでの比較が回らない。PRBM は 1 kHz で回せて、MuJoCo と PhysX の両方に同じ構造で載る。
- 代償：指の断面のつぶれと接触面の広がりは表せない。スキンの接触分布は節単位（1 節 2 点）の粗いものになる。

## D2. 接触剛性は「時定数」ではなく N/mm で与え、エンジンごとに測って合わせる

- 背景：最初の版は MuJoCo の solref の時定数を手で決めていた。監査すると、トマトの接触剛性が文献の約 1/10 で、全物体の摩擦が 1.0 だった。
- 決め手：MuJoCo の準静的な接触剛性は $K\propto m_{\rm eff}/t_c^2$ で、実効質量 $m_{\rm eff}$ に依存する。そこで「理想的な力ループで握って力 ÷ めり込みを測り、目標との比で直す」を繰り返して、実効質量を同定した（`scripts/calibrate_contacts.py`）。
  PhysX は剛性を直接与えられるが、接触点ごとに掛かるので、同じ手順で確かめた。
- 結果：両エンジンで目標の数 % 以内。物体の値は文献に合わせ（[physical_parameters.md](physical_parameters.md)）、文献のないものは仮定と明記した。

## D3. 筋肉のモデルは 4 つを同じ条件で比べる

- 比べた案：直線（$c\,p$）、静特性の表（不感帯＋飽和、遅れなし）、グレーボックス（5 パラメータ）、学習モデル（MLP）
- 決め手：「学習モデルが要るか」を主張する前に、物理の形を持つ小さなモデルと比べる必要がある。
- 結果：差は不感帯・飽和と遅れを表せるかで決まった。直線はいちごを全数潰し、残りの 3 つはどれも破損 0 だった。遅れを持たない静特性の表は、学習モデルより有意に成功が少なかった。学習モデルの利点は、構造を知らなくてよいことにある。構造が分かっている模擬筋肉では、グレーボックスで足りる。実機の筋肉で比べるまでは、どちらが良いかは決まらない。

## D4. 把持力は力センサではなく固有感覚で推定し、作用点だけを触覚で補う

- 比べた案：指先のロードセル、スキンの合計値、固有感覚（作用点を指先に固定）、固有感覚（作用点をスキンで求める）
- 決め手：食品ラインの指は洗浄と交換が前提で、指先に配線した力センサは避けたい。スキンの合計値は、感度のばらつきと飽和があり、力の大きさの測定には足りない。
  一方、力が「どこに」掛かっているかは、スキンの出力の分布で十分に分かる（各点のてこの和をスキンの出力で重み付けて平均する）。曲げ不足を力に直す式は作用点に強く依存する（$\Lambda(s)=\sum_j (s-s_j)^+$）。
- 結果：作用点を指先に固定した推定は、真値より系統的に低く、その分だけ強く握っていた。スキンで作用点を求めると、推定誤差は半分以下になった。許容力の幅が狭い過熟の物体では、この偏りがそのまま破損の差になる（Q2 の `plunger_clf_tip`）。

## D5. 硬さは指で触るのではなく、掌のプランジャで測る

- 背景：最初は 0.8 N まで弱く握り、曲げとスキンの力の傾きを硬さとした（指プローブ）。
- 決め手：指先のコンプライアンス $\Sigma l_j^2/k_b$ は 0.041 m/N で、果実の 16〜61 倍ある。果実のへこみは指自身のたわみに埋もれる。
  剛性比と雑音を掃引した判別マップで、想定した雑音（曲げ 0.3°）では文献の熟度差（1.3〜3.1 倍）を指で見分けきれないことを確かめた。
  プランジャは位置制御で押すので、変位がほぼ果実のへこみになる。
- 代償：1 回の把持が約 5 s 長くなる。見た目で区分が確実なもの（卵、ボルト）は押さずに済ませる余地がある（未実装）。
- 補足：プランジャで決めた $F^*$ に合わせて、握る高さも決め直す。初版は見た目の $F^*$ で決めた高さのまま握っていたので、軽いいちごを搬送中に落としていた。

## D6. 端から端まで学習する方策ではなく、分けた構成にする

- 比べた案：画像＋触覚 → 内圧指令を直接出す模倣学習、「判断は学習・実行は制御」の分割
- 決め手：
  1. 「潰さない」は安全側の制約なので、上限を人が読める形（取扱い表、つかみ直しの上限）で持っておきたい。
  2. 力のループ（50 Hz）は、学習モデルの推論時間に左右させたくない。
  3. 隠れた状態（硬さ）は押した瞬間にしか現れない。端から端の方策でこれを拾うには、その区間を強調したデータ設計が要る。
- 学習を入れた場所：筋肉のモデル、区分の分類、力の窓。どれも「入力 → 1 つの数」の小さな問題にした。

## D7. 一つの制御コアを、二つの物理エンジンで共有する

- 背景：最初の版では、Isaac Sim 用に制御器と推定器を書き写していた。乱数の種の扱いも違い、同じシードでも別の個体になっていた。両エンジンの差が「物理の差」なのか「コードの差」なのか、区別できなかった。
- 決め手：物体の個体・筋肉・センサ・推定器・制御器・成否を `twin_core.py` にまとめ、エンジンには小さなインタフェース（掌の目標、自由曲げ、時間を進める、関節角・スキン・接触力を返す）だけを持たせた。実機の制御器（`core/grip_controller.py`）も同じファイルを呼ぶ。
- 代償：PhysX のスキンは接触点を指の座標に戻して振り分ける実装で、MuJoCo の touch センサとは厳密には同じでない（指どうしの接触は数えない）。

## D8. PhysX は描画なしで動かし、作業はファイルで受け渡す

- 背景：この PC の GPU ドライバでは、Isaac Sim 5.0 の RTX 描画が初期化で落ちる。
- 決め手：描画を読み込まない最小構成の Kit アプリ（omni.usd、omni.physx、omni.physics.tensors）で PhysX だけを動かし、物理は 1 kHz で手で進める。
  計画（`v2_plan.json`）、進み具合（`v2_status.json`）、1 試行 1 行の結果（`v2_rows.jsonl`、再開可能）をファイルでやり取りする。
- 動画には、PhysX が計算した姿勢を MuJoCo の描画器で表示したものを使い、その旨を画面に書いた。

## D9. 評価は点推定ではなく、対応のある検定と区間で出す

- 1 条件の試行数は 50〜210 で、成功率の数ポイントの差は誤差の範囲に入りうる。
- 比率には Wilson の区間、2 方式の比較には同じ（物体、シード）を組にした McNemar の正確検定、差の区間には Newcombe の方法を使い、比較の族に Holm の補正をかけた。
- 本文と README の数字は手で書かず、`metrics.json` から書き出す（`scripts/make_numbers.py`）。結果を更新したのに文章が古い、ということが起きない。

## D10. 過熟トマトは中玉にする

- 背景：最初は大玉（約 90 g）にしていた。
- 決め手：指 3 本のつまみで持ち上げるには、摩擦で重さを支える把持力（およそ $mg/\mu$）が要る。大玉の過熟トマトでは、それが許容力 2.0 N にほぼ等しかった。予備実験では、目標を正しく選んでも搬送中に落とすか潰すかのどちらかになった。
  これは制御の問題ではなく、この手と把持の仕方の物理的な限界である。中玉（約 43 g）なら、正しく選べば運べる幅が残る。
- 意味：大玉の過熟を扱うなら、包み込む把持（指を赤道より下に回す）か、下から支える手先が要る。
